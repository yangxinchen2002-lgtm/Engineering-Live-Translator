## 使用

2026-11-04 已加入本地文件入口，继续使用同一个内置窗口，详见 [本地视频预读](LOCAL_VIDEO_LOOKAHEAD.md)。主界面“打开本地视频”或播放器顶部“本地视频”选文件，点击“开始字幕”，再自行播放即可。停止字幕不关闭文件服务。推荐单音轨 H.264 / AAC MP4；多音轨预读明确报错。

1. 继续双击原 ELT.exe / 原桌面快捷方式。在“课程”页选择“视频预读（网页 / 本地）”，播放方式为“ELT 内置窗口（网页 / 本地）”。
2. 点击“打开课程窗口”，点击上方 TUM-Live / Moodle 按钮或输入课程网页地址。首次在此窗口自行登录，在原网页播放器播放课程。
3. 主界面选择语言、原有翻译 API 与模型、启用中文翻译。在“朗读”页启用自动朗读，模型选择本地 Qwen 0.6B / 1.7B 或 Windows 系统音色，再选相应声音。Qwen 可选 GPU / CPU；系统音色不加载 Qwen。
4. 主界面点击“启动视频预读”。内置窗口自动发现当前支持的媒体，不需要配对或复制媒体链接。新页面导航保留已开始的跟随意图；手动停止后不会因导航自动恢复。
5. Token / 费用估算、原文与中文、最近字幕及可选稿件保存仍使用主界面。主界面停止会释放后台与 TTS，课程窗口的视频继续由原播放器控制；窗内也可单独停止/恢复字幕。关闭课程窗口会结束该网页，关闭 ELT 会关闭它自己的课程窗口。

首次生成模型准备可能较久。ELT 不会为此自动暂停视频。正常语速能读完时保持正常速度并等待下一句，只在时间不足时加速；整句音频使用一致语速。浏览器阻止自动发声时，字幕面板会出现“允许中文朗读”按钮，请自行点击。

内置窗口的登录与原 Edge 独立，不能继承已登录的 Edge 会话；本机浏览器资料位于 ELT 的用户设置目录，程序不导出 Cookie 或读取网页密码，关闭了密码自动保存。原 Edge 扩展仍可在“课程播放方式”选择，应用音频模式也保留。

## 实现与生命周期

- 原 `app/ui/window.py`、preferences 与 BackendController 继续管理语言、翻译、TTS 选项、用量和存稿。
- `app/ui/web_player.py` 受主界面管理，内部启动 `app.web_follow.player`；不是另一个用户安装项目。播放器与识别后端分开拥有 Windows Job，停止字幕不关闭课程页；关闭软件会回收内部窗口及其网页子进程。通过有上限 stdin 控制，不通过命令行传服务令牌。
- `app/web_follow/player.py` 用已安装的微软 WebView2 读取视频/iframe 时间和媒体，拒绝额外网页设备权限，保持 HTTPS 证书检查；服务令牌只在本机 Python 内存和 HTTP 请求头中，不注入课程网页。导航前的迟到结果由页内实例 ID 隔离。
- `app/web_follow/tts.py` 复用原 `.venv-tts`、SpeechEngine、Qwen 模型及音色，通过独立进程预生成完整 WAV。队列 8 句、单句音频约 2 MB、会话缓存 16 MB。模型加载以会话停止作为取消条件（最多 180 秒），首句过期不再导致重载；已经过期的生成任务在 45 秒上限内排空至 DONE 后丢弃结果，复用热模型。停止会话则立即取消等待并回收进程。连续真实失败 3 次停止重试并保留字幕，需停止后重新开始。
- 字幕先发布，语音完成后独立更新已有 cue；不会因等语音阻塞原文/中文，不把旧语音替换到新句。原文、翻译失败与语音失败分别保留。原始音频不上传；本地临时 WAV 在正常停止时清理。

Qt 6.8.3 的本机网页组件实测 H.264 `canPlayType` 为空，无法承担常见课程 MP4，因此采用本机已有 WebView2 156.0.4314.58。固定新增 pywebview 6.1 / pythonnet 3.0.5 及其锁定依赖；没有替换 CUDA、Whisper、Torch 或重新下载模型。依赖一致性检查通过。

## 朗读启动修正及 1.7B 实测（2026-11-03）

用户继续请求朗读，当前“自动朗读”已经勾选，使用 GPU、1.7B 讲课男声。发现原先加载模型和生成语音共用首句过期检查：连续播放时，首句可能在模型加载完成前过期，程序关闭模型后又重新加载。现在预热属于整个会话，过期句仅跳过；已开始生成的旧请求排空至其 DONE，防止旧数据混入下一句，也避免每次过期都重载。设备、模型与 PID 状态在跳过后保留；课程关闭时界面不会继续显示旧“已就绪”。
