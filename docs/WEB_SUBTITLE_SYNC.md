# 内置课程字幕延后修正 — 2026-11-03

用户报告原文和中文都稳定晚约 2–3 秒。本轮区分预读积压与播放器时钟，未把全部字幕硬提前固定秒数，也未修改原音频采样时间。

后续用户重开窗口仍确认相同延迟，故以下预读修正不能视为固定偏移已解决。随后用真实播放音频测得约 2.0 秒的时间坐标差，并在后台应用自动换算，详见 [真实声音对时修正](WEB_AUDIO_CLOCK_ALIGNMENT.md)。

## 实际发现与修正

1. 现场主界面显示预读余量从约 2.4 秒耗尽，跳窗不断增加；旧工作进程退出后，继续播放的时钟又把错误状态改回 preparing，使原始错误原因被退出消息覆盖。原始退出原因无法从旧记录确认。本轮令错误状态保持，只有明确重新开始才新建会话。
2. 旧网页工作进程要等本批所有翻译完成才提交 batch，下一批 ASR 随之等待。现在确认原文后立即提交音频覆盖范围，独立的翻译线程有界排队（8 句、单并发），网络不会阻塞下一批源音频识别。保留整句识别和翻译，不缩短成零碎语段。
3. 译文和语音允许在后续 ASR 批次提交后回写原 cue；按句段 ID、代际和原文核对，不把前句补译写到后句，也不被新的原文批次清空。保留最近 30 秒供迟到结果更新，容量仍为 96，不删除未来句子来假装完成。
4. 原内置窗口一律使用最大视频画面的时钟。TUM 双画面中，最大画面可能是静音跟随画面，其时间可以与真正发声音轨有差异。现在分别选择显示画面与声音时钟：优先唯一可听/实际解码音频的元素，静音时保持已识别的主时钟；同页与跨 iframe 均支持。字幕仍放在大画面，跨 iframe 使用最近主时钟和有界单调时间推算，过期时停止中文朗读而不干预原视频。
5. 媒体发现先使用所选播放器绑定的来源和 `<source>`，再回退到资源列表，降低拿到另一个视频播放列表的风险。无法可靠区分音轨时保留既有选择或最大画面，不伪造一个校准量。
6. 显示与诊断分别记录原文预读、中文预读、翻译排队、源音频准备时间及译文准备时间；计费快照按 revision 单调更新，旧 ASR 批次不回退已报告 Token。
7. 后台重启后，保留下来的真实错误揭示一次 HLS 解码窗口中有 7 个采样点的时间戳缝隙（16 kHz 下约 0.4375 ms），旧版的 2 采样点上限使预读停止。现在仅对 HLS 允许最多 8 个采样点（0.5 ms）的内部缝隙进行插值，必须两端都有实际数据，累计仍不超过每秒 2 个采样点。普通文件仍使用 2 点上限；更大、窗口边缘或累计超限的缺口继续明确报错。诊断累计记录修复点数和窗口数，不改媒体时间轴。界面错误时明确显示预读停止。

TUM 官方的[双画面同步实现](https://github.com/TUM-Dev/gocast/blob/dev/frontend/src/components/watch/split/sync.ts)明确区分主音轨与静音跟随画面，并周期校正跟随画面。这为主时钟选择提供依据，不能直接证明用户这次偏移完全由它造成。

## 测试和证据

- 完整 Python 回归 899 通过、3 跳过（最终主时钟补丁之前）；最终相关模块 139 通过，Node 41 项通过。覆盖 HLS 的 7 点修复、9 点/边缘/累计超限拒绝，以及错误不能继续标为加载中。
- 自动调度测试故意阻塞首条翻译，真实 worker 调度代码仍提交连续两个 ASR 原文窗口；该测试的 ASR/API 只在测试内替换，不能当作真实 GPU 性能。
- 同页/跨 iframe 双画面复现：大画面时间 3 秒、发声音轨 5.5 秒，按声音时间选择和渲染，不向原视频写入播放、暂停、进度、音量或倍速。
- 真实 CUDA + 公开英语 MP4 + DeepSeek：先在测试时间 20 秒等待初次准备 15.734 秒，再让测试媒体时钟以 1 倍连续前进 35 秒。4 句原文和译文均在 ASR 句首前准备好；句首准备迟到超过 250 ms 的数量为 0，最小预读余量约 8.711 秒，跳窗 0，停止后工作 PID 消失。未启用朗读。
- 以上连续测试测量后台是否提前准备，未测浏览器绘制或人耳判定的语音对齐；只有 35 秒，不能代替完整课程、HLS 或长测，也不是整个系统延迟为 0 的结论。
- 原课程字幕后台已单独重启，保留原课程窗口和视频播放；首次重启约 49 秒时预读余量 10.4 秒，随后捕获上述 7 点缝隙错误。HLS 修正后再次只重启后台，约 34 秒时余量 9.6 秒，初次模型准备阶段有 1 次追赶跳窗。没有自动刷新或关闭用户视频；后续现场记录见验收 JSON。
- HLS 修正后现场约 75 秒的数值快照：状态 ready，无错误，原文/中文预读均为 7.710 秒，翻译排队 0；9 个窗口累计插值 25 个采样点，初次追赶跳窗仍为 1。按处理窗口计数，可能包含上下文重叠，不是唯一音频缺口数量。已确认该修复在真实课程媒体中运行，未自动重新加载旧观察脚本。
- 现场约 168 秒时仍为 ready、无错误，原文预读 3.2 秒，跳窗仍为 1。实际 HLS 余量会随窗口准备而变化，这些是离散快照，不构成稳定性或延迟分布结论。

证据位于 `artifacts/web-sync-fix/`：`python-full.xml`、`python-release.xml`、`continuous-real.json`、`acceptance.json`。只保存数字和状态，不保存用户课程字幕、签名媒体链接或密钥。公开样本复现工具：`tools/check_web_sync.py`，会使用已有 DeepSeek 密钥产生少量文本翻译费用。

## 如何载入

识别/翻译解耦已通过重启后台载入。主时钟选择属于播放器进程中的网页脚本，当前打开的旧窗口仍运行旧脚本；单纯停止/恢复字幕不能替换它。

请在方便时关闭 ELT 的课程子窗口，再到主界面点击“打开课程窗口”，进入课程并回到需要的位置。登录资料保留。若主界面已停止，再点击“启动网页跟随”。程序不会替用户刷新正在播放的视频。下次重新打开整个 ELT 还会看到分开的原文/中文预读指标。

仍需真实课程听看验收固定偏移是否消失；Whisper 单词时间本身、HLS 时间戳或网站特殊裁剪时间仍可能带来偏移，不以这轮单元测试代替确认。原来 M3 的 60 分钟和课程质量验收保持待执行。
