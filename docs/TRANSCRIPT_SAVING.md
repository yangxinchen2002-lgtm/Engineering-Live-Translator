# 每次翻译稿自动保存 — 2026-10-31

2026-11-03 新增日语后，固定语言还可为“日语”，Auto 可生成“英语+日语”等组合；文件时长、同名保护、默认关闭和保存内容规则沿用本报告。新增测试与操作见 [JAPANESE_SUPPORT.md](JAPANESE_SUPPORT.md)，下文测试数字是首次交付历史记录。

## 本次完成

- 底部“翻译稿设置”入口；默认关闭的“自动保存每次翻译稿”开关。首次启用要求选择目录，取消则不开启；以后记住目录和开关。运行中锁定本次设置，下一次可关闭或更换位置。
- 每次开始/停止为独立会话，保存 UTF-8 双语 TXT。CLI `translate-live` / `translate-file` 通过可选 `--transcript-directory` 指定现存目录，原有 JSONL 历史和诊断开关独立。
- 完整会话独立于界面的 128 条记录和最近 1–12 条显示限制；按原文样本顺序整理，版本去重，乱序译文不会打乱最终稿。
- 只保存已确认原文和对应最终译文，未完成中文明确标注。候选尾部和旧的部分译文不会伪装为完整内容。未开启中文时可保存已确认原文，中文部分标注未完成。
- 文件名例如 `2026-10-31-德语-12分钟.txt`。日期为会话开始的本地日期；音源就绪到结束的实际运行时长按分钟向下取整（59 秒为 0 分钟，60 秒为 1 分钟），包含暂停时间，排除音源就绪前准备及结束后的翻译排空。文件离线处理时也按实际处理运行时长，不冒充媒体总长。
- 固定语言用“德语”或“英语”；Auto 按原文语言汇总，混合为“德语+英语”，无原文为“未识别语言”。同名依次加 ` (2)`、` (3)`，不覆盖原文件，包括多个会话并发结束的情况。
- 运行时本地 SQLite 逐条提交，完整句对同时写进行中 TXT；停止后生成正式文件、显示路径并清理本次临时文件。所有正文只在指定目录，默认不开启，不录音、不上传文件、不增加 API 调用。
- 队列有容量上限，后台串行文件操作。目录不可用、写入失败、队列溢出及未收到完成状态会明确提示，保存错误不停止原文识别和翻译。

## 性能数据和已知边界

本轮没有新增真实语音延迟、GPU 显存、翻译质量、磁盘吞吐或 60 分钟稳定性数据。测试耗时仅为自动回归耗时。队列默认 64 项，过载会明确标记不完整，不承诺在任意慢磁盘上永不丢保存记录。

进行中 TXT 以译文完成顺序追加，最终稿才按原文整理；尚未译完原文保存在本地临时库，结束时写入正式稿。强制结束、断电、文件夹失效或 GUI 的 20 秒关闭保护触发时，可能留下 `日期-翻译稿-进行中-随机身份.txt`、`.elt-transcript-随机身份.sqlite3` / journal 或 `.ready`。尚无自动恢复，不保证强制退出后生成正式文件。正常停止也可能缺少尚未确认的候选末尾，稿件会说明停止/中断。正文文件保存完整并不代表所有中文已译完或语义已人工校验。

启用开关作用于之后的会话，不能补回过去已结束会话。目录不存在或无权限时会提示并继续翻译；不会偷偷改存其他位置。偏好只保存开关与目录，实际稿件在用户所选位置。停止后可自行删除不需要的稿件/本次残留；清除偏好不会删除稿件。

## Windows 人工验收步骤

1. 停止当前字幕、退出再双击根目录 `启动ELT.cmd`。点底部“翻译稿设置”，勾选“自动保存每次翻译稿”，在系统对话框选择自己的文件夹；也验证取消时不会勾选成功。
2. 选择 VLC / Chrome / Edge、德语或英语；需双语时主动勾选“启用中文翻译”。播放并翻译至少 1–2 分钟，随后点“停止”，等待界面显示已保存路径。
3. 打开该 TXT，核对原文、中文配对及播放顺序，确认正式名称为会话开始日期、语言、实际整分钟。检查未完成的中文有标注。正常完成后，本次进行中 TXT / SQLite 应已整理清理。
4. 退出重开，确认开关和文件夹恢复，但不会自动开始字幕或启用中文；下一次会话无需重复选目录。同一天、同一语言、相同分钟数再次保存，确认增加序号且上次稿件未改变。
5. 停止后取消保存勾选，再开始/停止短会话，确认目录没有新稿件。重新勾选时复用记住的目录；“选择保存文件夹”可修改下一次位置。
6. 使用 Auto 的德/英或混合内容，检查文件名语言；暂停后继续播放，确认按音频会话实际运行分钟命名。无有效原文的短会话应明确显示无原文，不假装有译文。
7. 若保存目录暂不可用，核对明确保存错误、原文/翻译继续且不显示假成功。恢复目录后开始新会话再验证。不要通过强杀替代正常“停止”。
