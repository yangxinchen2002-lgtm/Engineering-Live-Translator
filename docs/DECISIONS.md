# 技术决策

## D043 — 界面语言与翻译目标分别保存，按会话固定译文和朗读语言

界面使用本地静态词条。Qt 在下次启动时按保存语言构建，避免重建运行中窗口或中断课程；原文、译文、路径及课程页面不参加替换。目标在启动前选择、会话内锁定，避免旧中文响应或声音进入英文会话。Qwen 显式传语言，SAPI 按 LCID 校验；英文术语取自现有同领域双语词条，缺项省略。中文默认和文件命名兼容。网页词条与已安装扩展由一个工具同步，词条覆盖、默认参数、数据隔离有回归。见 [LANGUAGE_OPTIONS.md](LANGUAGE_OPTIONS.md)。

## D042 — 朗读模型属于会话，句子过期不重载模型

连续播放时，模型预热可能长于第一句剩余时间。把二者共用过期回调会导致首句到期即关闭模型，下一句重新加载。改为独立会话预热；过期请求限时排空至真实 DONE，丢弃其音频后复用模型，确保下一请求不会读到旧 PCM。会话停止仍立即取消等待、回收子进程；真实协议错误/超时继续释放模型并有 3 次失败上限，不伪装为就绪。实测及限制见 [INTEGRATED_WEB_PLAYER.md](INTEGRATED_WEB_PLAYER.md)。

## D041 — 用实际声音确认时间坐标映射

用户重试排除了“重新载入主音轨选择就已修复”的假设。真实内置播放器音频与预读 PCM 的两次独立测量分别为 +2.024 / +2.005 秒，故采用实测映射，不猜固定提前量。只匹配本 GUI 内唯一播放器的活动音频会话，两个独立片段确认后才应用，静音/重复音/不稳时钟不补偿。ASR/TTS 准备保留源时间，预读调度用映射源时钟，网页显示与朗读使用换算后的同一时段。当前仅在原声、1 倍速时测量，成功后允许播放倍速变化；不跨会话继承结果或保存音频。详见 [WEB_AUDIO_CLOCK_ALIGNMENT.md](WEB_AUDIO_CLOCK_ALIGNMENT.md)。

## D040 — 源音频预读不等待网络，声音时钟与显示画面分别选择

用户报告稳定 2–3 秒的双语字幕延后。现场还存在预读耗尽和退出错误被时钟覆盖，故修复确定的串行依赖与错误保留，并独立验证多画面时钟。ASR batch 表示真实源音频准备完成；翻译、用量、语音是后续独立事件，保持有界、原句归属和原始采样时间，耗时分别记录。保留整句策略，未采用无依据的全局时间平移。内置播放器只读选择可听音轨，最大画面仅决定字幕位置；跨框架传递有时效的主时钟，不操纵网站播放器。用户正在播放时仅更新后台，网页脚本更新留待用户选择重开窗口。实测及限制见 [WEB_SUBTITLE_SYNC.md](WEB_SUBTITLE_SYNC.md)。

HLS 实测出现 7 点（0.4375 ms）内部时间戳缝隙，原 2 点严格上限导致预读终止。仅 HLS 放宽到 8 点，累计仍限制每秒 2 点、禁止窗口边缘插值并显式累计诊断；较大缺口仍停止，不以填入整段静音掩盖丢失。

## D039 — 同一个 ELT 内的 WebView2 课程窗口和有界 Qwen 预合成

用户要求将可行的隔离试验与 TTS 融合到原程序，不再以独立项目交付。保留原 EXE、凭据、设置与主 GUI；新增的是受主程序管理的课程子窗口。当前 Qt 6.8.3 网页组件实测 H.264 canPlayType 为空，故复用系统 WebView2 156.0.4314.58，经固定 pywebview 6.1 / pythonnet 3.0.5 承载网页，不编译/替换 Qt 或下载浏览器。已有 Edge 扩展作为可选兼容方式。

Qwen 在原 .venv-tts、原模型与音色上运行，独立队列在翻译发布之后预合成，避免把 GPU 语音耗时串入原文/翻译显示。整句音频作为一个媒体时间单元，只在来不及读完时加速。窗内只读视频；暂停、跳转与倍速由用户操作原播放器。跨域 iframe 观察在 WebView2 官方帧接口上实现，凭据和本机服务令牌不注入课程页；网页摄像头/麦克风等额外权限拒绝，HTTPS 证书检查保留。新窗口登录数据与原 Edge 独立，不复制浏览器会话。

## D038 — 网页预读成为正式软件的第二输入模式

2026-11-03 用户在 TUM-Live 和 Moodle 的隔离实验验证字幕、朗读及停止不影响视频后，授权接入正式程序。将实现迁入 app/web_follow，由既有 GUI 的 QProcess/Windows Job 管理；应用音频入口保留，识别通过跨进程互斥避免重复加载。网页模式沿用实验已验证的系统中文声音，避免同时加载 Qwen；原音频模式继续原 TTS。共同复用语言、翻译来源/凭据、术语表、Token、历史和存稿；配置通过有限 stdin 发送，不传密钥或在诊断中记录配对令牌。

原网页是唯一播放控制者，网页字幕与朗读按只读媒体时钟推进；原文整句确认独立于翻译成功，未来内容不进入显示或稿件。从中途开始、跳转或处理跳窗显式标不完整。原扩展目录通过发布同步保持兼容，仅保留一份 Python 实现，不要求用户重新安装扩展或重填密钥。新增连接页只做显式配对，正式界面参数优先；不增加浏览器权限，不将原始音频上传。兼容入口和历史验收仍保留。测试与支持边界见 [WEB_FOLLOW.md](WEB_FOLLOW.md)。

## D037 — 分来源凭据与官方原生流协议

2026-11-03 用户要求保存DeepSeek/GPT/Claude/Gemini多个密钥并选择翻译API。为每来源保留一个独立Windows凭据、单独模型记忆；会话固定选择，避免混用上下文和计费。保留旧DeepSeek target，使用现有HTTPX分别适配OpenAI Responses、Anthropic Messages和Gemini生成接口，不增加大型SDK、不伪装所有服务为DeepSeek兼容接口。官方HTTPS地址注册校验、凭据来源匹配、重定向拒绝，密钥不进入URL/配置/参数；其他来源的Token按协议归一化，未知价格不套DeepSeek卡片。没有真实新服务密钥时只报告本地协议/状态测试，不宣布真实账号和质量验收通过。实现及证据见 [MULTI_PROVIDER_TRANSLATION.md](MULTI_PROVIDER_TRANSLATION.md)。

## D036 — 回看与实时焦点分开渲染

## D035 — 严格最近上下文与独立于响应先后的字幕显示

2026-11-03 用户要求动态删除最早上下文并排查长句漏译。旧请求已有限历史，但会跳过新长句后选旧短句；改为连续最近句对，并在内存/请求同时按字符与条数裁剪，另限完整messages，不裁当前句。原来没有逐次大小/超时阶段证据，不把未证实的假设当作故障原因。保留并发以便实时原文继续，UI按原句等待而不按完成先后抢位；等待后的译文给出有限阅读时间，8项恢复队列分批补充，显示历史仍有上限。临时重试标记独立于终止错误，字幕与朗读都不能因第一个重试错误就跳过或永久阻塞。失败/显示等待分别可诊断，不增加付费调用。验证及未执行项见 [TRANSLATION_CONTEXT_AND_ORDER.md](TRANSLATION_CONTEXT_AND_ORDER.md)。

## D034 — 暂停收音连接，保留模型；原文回退独立于翻译成功

2026-11-03 用户要求暂停/继续、可拖动焦点、翻译失败保留原文和悬窗基础语速。采用关闭/重建现有原生连接的方式暂停，避免暂停期间无限缓冲或修改稳定的ELT/1原生协议；保留模型，重新验证进程身份。必须明确请用户同步暂停视频，暂停音频不属于转写范围，稿件记录这一边界。采样序号接续而真实QPC保留间隔，VAD/窗口在边界分开。翻译故障不伪装Final：原文卡片可显示但中文成功仍需原revision检查，后到有效中文更新同卡，旧句不抢回焦点。位置归一化保存，边缘限制保证正文可读；基础语速仍由既有独立朗读模块管理。实测与局限见 [FOCUS_PAUSE_AND_RECOVERY.md](FOCUS_PAUSE_AND_RECOVERY.md)。

## D001 — M0 时的范围约束
最初任务明确仅实施 M0，当时没有引入 PySide6、Faster-Whisper、CUDA 或 DeepSeek，也没有建立空的未来模块。后续用户明确授权的 M1 范围变更记录于 D008；M2/M3 仍未开始。

## D002 — Python 3.12 与 SciPy
本机有 Python 3.12.10；以该版本和现有固定版本依赖完成自动测试。任务允许经过验证的兼容版本，因此不额外安装 Python 3.11，不宣称其已验证。SciPy 的 FIR/upfirdn 提供真实抗混叠重采样；封装少量有界历史与相位连续逻辑，并与整段因果滤波和频率响应测试比对。

## D003 — 一会话一 helper，命名管道
命名管道符合首选方案，当前用户 ACL、拒绝远程连接。无需虚拟声卡、额外服务、TCP 端口或 Python 原生扩展 ABI。单次 helper 退出便于隔离 WASAPI 故障和重复启动，代价是每次启动有进程创建/激活开销，未声称延迟已优化。

## D004 — 格式读取失败的有限回退
先调用虚拟进程捕获客户端 GetMixFormat；若成功，按真实返回格式 Initialize，读取/传输该格式。若仅返回 E_NOTIMPL，则原方案“必须先获得 GetMixFormat”无法继续，改为按微软示例显式请求 44100 Hz stereo S16 + AUTOCONVERTPCM。只有 Initialize 成功才传输该协商流格式，并发出 format_negotiation 和 format_source=Initialize_accepted，绝不称为读取到了设备 mix format，也不把它当作 VLC 解码源文件原始格式。其他 HRESULT 一律错误。

依据：[官方源代码](https://github.com/microsoft/Windows-classic-samples/blob/main/Samples/ApplicationLoopback/cpp/LoopbackCapture.cpp) 中的显式 PCM 初始化模式；E_NOTIMPL 分支是兼容实现，必须单独记录实际是否触发。影响：可能由 Windows 先重采样一次，再由 Python 转为 16 kHz；该路径需实机验证。不能为满足表面要求而伪造“实际读取成功”。

## D005 — 数据完整性优先
有限 SPSC 队列不让捕获线程等候管道；满载就终止并报告音频不完整。首包 discontinuity 是会话原点，后续 discontinuity 必须失败。遇到 QPC 错误不编造时间戳。暂停期间是否有静音包由 Windows 决定，累计样本和墙钟分别报告。

## D006 — 调试留存与第三方工具
日志和 WAV 仅按 CLI 显式路径保存，拒绝覆盖，WAV 有 30 秒上限。测试音是 fixtures，不是生产采集数据。VLC 3.0.24 是用户明确授权的官方便携下载，校验 SHA-256；MSVC/SDK/CMake 由用户明确指示使用 Build Tools 安装。第三方二进制不纳入源代码交付，按其各自许可证使用。

## D007 — 频谱异常不改写为成功
补充短测的固定 ±3 Hz 分析带出现假串音风险：实测原生主频约 1005–1008 Hz，之后回到 1000 Hz，标准化输出与原生主频逐窗相同。保留频带、阈值和失败证据，新增主频诊断与 inconclusive 状态，返回非成功码。不能把弱目标频带分母造成的比值升高直接解释成另一个程序的 440 Hz 信号。

[VLC 官方音频同步实现](https://github.com/videolan/vlc/blob/3.0.x/src/audio_output/dec.c) 存在随时钟漂移调整重采样的逻辑；它是本次上游频偏的一个**可能解释（推断）**，本次没有单独定位到该代码或排除 Windows 音频引擎的影响。M0 不通过修改 VLC 用户设置或扩大统计口径掩盖问题。

## D008 — 用户授权进入 M1，M2/M3 保持未开始
用户明确指示继续 M1，并要求自行寻找公开带文本素材。保留 M0 基线与已知限制，新增本地转写和评估；不推断为允许进入翻译或 GUI 阶段。

## D009 — 固定 GPU 运行组合与本地模型
实际验证 Faster-Whisper 1.2.1 / CTranslate2 4.6.0 / CUDA Runtime 12.4.127 / cuBLAS 12.4.5.8 / cuDNN 9.1.0.70。NVIDIA 官方归档 SHA-256 校验后仅项目本地解压。setuptools 84 移除 pkg_resources 导致真实导入失败，因此固定兼容的 80.9.0，不以未经测试的最新组合替代。运行时只加载本地固定 checkpoint；错误不默默切设备或模型。

## D010 — 确认与提交分离
Local Agreement 的 stable 只代表相邻假设一致，不是正确概率。停顿/EOF 提交、没有双次确认的旧窗口候选使用 committed 与独立 reason。快速文件测试揭示跳过预览可能让旧候选离开窗口，已改为显式保留，不静默抹除，不冒充 LA。用有限历史时钟保留其真实音频时间，不从新窗口结尾向前猜时间。

## D011 — 重复幻觉通过真实、有限重试处理
英语极短 EOF 窗口出现大量循环词。检测显著异常词速/重复后只再做一次真实模型解码，开启 repetition_penalty=1.05/no_repeat_ngram_size=4，日志标记；仍异常就失败。没有正则删词或用参考文本修补输出。正常窗口保持 beam1/temperature0，不给模型喂评估答案。

## D012 — 统一 QPC，拒绝假负延迟
真实 VLC 测试发现本机 Python 3.12 的 monotonic_ns=GetTickCount64，而 perf_counter_ns=QueryPerformanceCounter，实测时基相差约 36 秒。原 Live V1 将 WASAPI QPC 与 GetTickCount64 混算，产生错误负延迟；这些结果保留但不计时钟通过。改为 app/asr/clock.py 集中提供单调 QPC，覆盖输入、任务、worker、显示和 M1 日志，并验证捕获时间戳年龄、拒绝 <−0.1s 的模型延迟。文件长测原先输入/输出同用 GetTickCount64，没有跨时基混算；其 15.625ms 计时分辨率和代码版本在报告单独注明。最终 VLC 链路重跑，不用错误数据宣称低延迟。

## D013 — 课程词表只作有界、显式的 ASR 提示
用户授权尝试降低 M1 识别错误。使用固定 Faster-Whisper 1.2.1 的 hotwords 参数，不改模型、beam、VAD、窗口或文本后处理；默认关闭，由课程明确选择。16 KiB/48 条/128 个真实 tokenizer token 上限，错误不静默回退或截断；Auto 语言锁定前不加提示。文件仅启动读取一次，日志记录散列及每次实际应用标记。此为本地 ASR 词表，不提前实施 M2 翻译术语系统。

质量对照重放相同识别窗口，轮换两组先后次序；前 900 秒为已知错误的开发集，后续完整字幕区间作未调参验证，参考不输入模型。保留错误率与多余词统计，不根据结果删词或改写参考。速度仅报实际推理耗时，不把离线重放冒充实时字幕延迟。

## D014 — 用户关闭 ASR 热词并授权 M2，无密钥实测范围
用户明确要求关闭热词、直接进入 M2，并选择本轮不配置密钥。配置与 M2 入口均禁用 ASR 课程提示；翻译术语独立维护。真实 DeepSeek/人工质量待验收，使用 Mock 测试响应协议与并发，真实设备只验证无密钥原文降级。没有假译文或让 Mock 进入生产流程。M3 未开始。

## D015 — 单一 HTTPX 客户端、严格流结束与有界任务
只需要 Chat Completions 文本 SSE，采用固定 HTTPX 0.28.1，避免额外 SDK 层；验证思考关闭、流式 UTF-8/消息边界、最后 finish 包或独立 usage、正常 stop 与 DONE。总请求超时包住整个流，心跳不延长总 deadline。认证/余额禁用新请求，限流/网络有限重试；16 待处理、2 并发、24s 时效，所有丢弃可诊断。错误体/密钥不进入日志，取消后缺失 usage 标未知费用。

## D016 — ASR 候选、稳定前缀和字幕锁定分离
ASR 更新新增真实词级采样与 endpoint，即使没有新词也能封口。候选尾部不送翻译，也不因候选修改重复请求同一稳定版本。source revision、candidate revision、request attempt 分开管理；旧版本/旧重试/重复完成无权回写。只有封口后完整请求正常结束才 Final；Final 是生命周期锁定而非语义保证。相同逻辑片段已有前缀译文携带自身来源/版本，不能当新全句译文；新片段不继承上句中文。

## D017 — 人工评估不伪装成自动质量认证
100 句为原创评估草案、非人工 gold；准备时实际译文为空，只有用户以后显式 --run 且有凭据才调用 API。数字和否定筛查只产生人工待查标记，不输出“翻译准确率”。当前报告区分真实设备、本地 HTTPX MockTransport 集成和未执行的真实 API/人工评审。

## D018 — 用户追加授权桌面交互界面，保持真实后台与明确验收边界

虚拟环境 python.exe 可能是启动器，实际解释器创建的后代不能只靠启动器 PID 回收。因此后台在创建任何 worker/helper 前自行加入 GUI 独占的 Windows Job，加入失败即退出；关闭采用正常 STOP/取消及有期限的 Job 强制结束。Windows Job 实际父/后代清理已有自动测试，真实 GUI 整链仍待用户桌面验收。

当前测试会话与用户桌面隔离，无法连接本机回环 socket，VLC RC 失败、asyncio socketpair 初始化阻塞。桌面启动另返回 app approval timed out。保留失败证据，交付可双击入口和离屏控件预览，不将它们写成真机字幕测试通过；不为通过测试修改正常生产事件循环或安全设置。详见 GUI_ACCEPTANCE.md。

## D019 — 修正 pywin32 凭据写入类型，保留安全的错误原因

pywin32 312 的 CredWrite 输入 CredentialBlob 为 Unicode str，CredRead 输出为 bytes，两者类型不同；不得因为读取时要解码就预先把写入值编码成 bytes。该错误已用真实绑定复现并修复，写入交给绑定内部编码，读取维持 UTF-16-LE 解码。凭据边界只保留操作类型和数字错误码，GUI 不输出底层异常文本或密钥；格式错误、Windows 拒绝访问和写入后验证失败分别报告。类型回归采用无效 flags 的真实 API 调用，不操作用户真实凭据，不发送云端请求。

## D020 — 浏览器按进程树捕获，不伪称单标签页隔离

用户明确授权直接播放网页视频。沿用 Application Loopback，对 Chrome/Edge 浏览器窗口所属主进程进行 PID+创建时间绑定，捕获其音频服务子进程；以可见顶层窗口所属 PID 排除渲染/工具进程和浏览器退出后的孤儿子进程。不读取命令行、URL 或浏览历史。GUI/CLI/native 均限定来源为 VLC/Chrome/Edge，不添加全系统回退，旧的无 source 原生调用仍默认 VLC。切换音源的迟到发现结果不能覆盖新来源，运行中不允许切换。多个窗口/标签页可能同属一棵树，界面明确范围。

## D021 — 多条字幕用既有片段身份复用控件

用户明确要求同时显示多句、减小字号和调整长宽。直接复用 SubtitleViewModel 的有界片段与 revision 保护，为每个身份保留一组原文/中文标签，按时间显示最近 1–12 条，默认 4 条；更新旧片段不重建整个字幕区。字号 6–72，长句换行，放不下时滚动；显示条数不等于保证相同数量的完整语法句。数值宽高与 QSizeGrip 都操作真实窗口，不缩放截图或截断字幕文本。Qt 使用逻辑像素，恢复位置时约束到现有屏幕；多显示器算法测试不能替代硬件验证。

## D022 — 穿透只改变自有 Windows 透明层窗口的输入样式

原方案 Qt.WindowTransparentForInput 在本机 6.8.3 撤销后，QWidget flags 与 native QWindow flags 可能不同步，导致后续绘制再次带上 WS_EX_TRANSPARENT。实际测试已复现；只在撤销时清掉 Windows bit 仍会复发。因此 Windows 路径始终不设置该 Qt flag，而对自有 HWND 的透明层窗口切换 WS_EX_TRANSPARENT，保留其他样式；这是微软记录的透明层窗口输入语义，参见 [Layered Windows](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows)。其他平台保留 Qt 回退用于组件测试。

RegisterHotKey + MOD_NOREPEAT 提供 Ctrl+Alt+E 恢复编辑和 Ctrl+Alt+S 显示/隐藏，不安装键盘钩子，关闭注销。占用失败保留可见恢复按钮并提示；该 API 的失败/占用规则见 [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。PySide6 nativeEventFilter 使用 `(handled, 0)` 返回形式；原 bool 形式在真实 WM_HOTKEY 测试中会重复回调，已修正并保留单次消费的原生回归。测试中 Ctrl+Alt+M 已被占用，因此最终选择 Ctrl+Alt+E。

自动化原生窗口短测中 startSystemMove 未产生位置变化，顶部改用 Qt 鼠标全局逻辑坐标实现有限的按下/移动/释放状态；开启穿透、隐藏或释放清除拖动状态。实际移动及右下角缩放均有几何变化证据。缩放继续采用 Qt 官方 [QSizeGrip](https://doc.qt.io/qtforpython-6.8/PySide6/QtWidgets/QSizeGrip.html)，没有新增 Windows 全局输入控制。

性能面板只消费实际事件，分类保留最近 512 样本，不新增 GPU 推理或云端探测。原文/中文核心可用、网络请求、队列和 Qt paint 分开；首条中文绘制需要版本及音频时间可对齐。无法对齐就记录未知，不把更新版本或历史内容当作首译。费用未估算，Token 只显示服务返回用量。用户明确把长测留到空闲，本轮只做自动回归和短测；没有新的低延迟、准确率或长时间稳定性达标结论。

## D024 — 整句翻译控制提交时机，不延迟原文或更换服务

用户关注一句反复变化的 API 花费，明确要求增加等待完整句子的模式。复用既有 source_closed、分段及版本机制，在 coordinator 处阻止 sentence 模式的开放片段进入队列，原文/候选仍照常发布。无需改变 ASR、音频、DeepSeek 模型、提示词、客户端或流式响应协议，也不通过抬高预览阈值假装永远关闭预览。

## D025 — 焦点显示使用共享位移，旧句向上保留

用户要求已完整处理的双语字幕居中，下一句非线性滑入，并明确否定淡出。实现独立 FocusViewport，使用 Qt QVariantAnimation + OutCubic 驱动一次共享垂直位移，所有句对卡片同量上移；不引入 opacity 动画、渐隐或缩放。旧句按所选历史条数保留，超出窗口由父窗口裁切。依据为 Qt 6.8 的 [QVariantAnimation](https://doc.qt.io/qtforpython-6.8/PySide6/QtCore/QVariantAnimation.html) 与 [QEasingCurve](https://doc.qt.io/qtforpython-6.8/PySide6/QtCore/QEasingCurve.html)。

焦点只接收已封口、Final 且译文版本匹配的双语记录，原文仍由主窗口实时显示；source-only 使用已结束的原文。晚回来的旧片段不能回退焦点，重复发布不能重启动画。等待最多 8 个动画，超限合并旧待播动画并记录诊断，字幕数据不受影响。历史卡片按 1–12 条限制，切换期间多一张；隐藏停止动画并取最新完成记录，恢复不重播历史。该开关默认关闭以保留原列表行为，用户开启后保存。

焦点可能显示早于当前实时原文的片段，原来的“最近事件时间”会错配延迟。因此控制器改为有界记录各片段的版本/接收时间，focus 就位 paint 独立统计并明确包含动画。无法取得或对齐时间时不编造。无需修改 ASR、DeepSeek 或音频捕获，也不因焦点模式增加 API 请求。

## D026 — 实时原文独立置于焦点下方，不挤动已完成句

用户确认焦点上推效果后，要求下方同时显示逐渐识别出的文字。保持中央仅接收完整句对，另用一组固定复用控件接收最新未完成原文，确认前缀与候选分别转义显示。以完成/滑入卡片的底边定位，候选长度变化不触发整个焦点重新排版，不重启上推动画或调用翻译。完成后该条从实时预览移交到原完成卡片，最新完成后不回退显示旧的未完成句。

使用下方独立裁切区域显示长原文末尾，保留完整记录，避免覆盖中心或随词数增长无限抬高窗口；空间不足按窗口边界裁切。预览只有一个记录/控件，不增加任务队列；隐藏/恢复、新会话、字体颜色和清空沿用焦点生命周期。它不触发完成句就位计时，防止把实时原文更新当作完整双语完成。

## D027 — 每次翻译稿独立持久化，结束时按原文排序命名

用户要求可选自动保存且记住目录。已有 UI 字幕模型最多 128 条，JSONL 历史只保存 Final；直接导出它们会遗漏长会话前部或翻译失败的原文。因此增加独立的 TranscriptWriter，默认关闭，经明确目录参数启用。继续使用现有事件和有界队列，标准库 SQLite 在磁盘去重保留整次会话，完成句对增量写入进行中 TXT；无需引入新依赖、无限内存历史或额外翻译请求。

关闭时从库按音频样本顺序生成双语 TXT，处理响应乱序并标出未译完原文；不保存候选或过期前缀译文冒充完成句。文件名为会话开始日期、固定/识别语言、实际音频会话整分钟，向下取整，暂停包含在会话时间中。结束时才能确定时长，所以运行中用随机身份的进行中文件；排他预留正式名称并重名加序号，防止覆盖。保存错误保留可用临时数据、报告不完整，识别/翻译继续；异常退出自动恢复留待后续明确需求，当前不承诺强杀后完整稿件。

## D034 — 内置媒体保留请求头验证，朗读设置独立于识别会话

2026-11-03 真实课程确认 1.7B 已生成 19 个音频文件，但原生播放器的全部读取失败。原因是原生 HTTP 客户端使用既有令牌请求头，而媒体路由只检查查询参数；独立合成或系统播放测试无法覆盖该边界。媒体改为优先读取请求头、缺省时允许媒体 URL 令牌，Host/Origin 和会话文件白名单保持校验；不让课程网页获得本机令牌，也不通过重载正在播放的视频应用修复。真实 HTTP 测试直接调用原生 Player 请求方法读取 WAV，验证内容、未授权拒绝与文件边界。

用户要求课程窗口顶部快捷朗读设置，复用原设置和本机服务。语速/音量合并更新 Audio，开关使用共享标志，模型/音色变更关闭旧合成器后重新准备；用独立 speech_revision 隔离迟到文件，保持 ASR 和字幕生命周期。增加生成、读取、播放各阶段计数，以真实网页 playing/ended 事件验证链路，技术记录与人工听感分开。实测与剩余边界见 [WEB_READING_CONTROLS.md](WEB_READING_CONTROLS.md)。

## D035 — 内置网页按视频元素降低原声，保留独立中文音量

用户要求与原应用模式相同的朗读时原声调节，并放入顶部。原来的 Windows 进程音量管理若用于 WebView2，可能同时降低该窗口的中文 Audio，因此内置模式改为只调整真实声音视频元素的 volume；跨框架由原生端把播放事件转交给声音所在框架。原先对播放器只读的要求按本次授权仅放宽原声音量，播放、暂停、跳转和倍速继续由用户控制。

沿用原有 duck_source 偏好语义和 10–100% 保留比例，记录未降低的基准，避免重复缩小；手动改变原声则更新基准。停止或切换框架时释放，页内以 1.5 秒续约机制在原生连接失效时恢复。顶部设置经现有严格校验的本机接口同步，不重建 ASR 或翻译。实际控件、真实视频与自动测试结果见 [WEB_SOURCE_VOLUME.md](WEB_SOURCE_VOLUME.md)。

## D037 — 扩展复用正式朗读接口与同一原声音量实现

扩展的弹窗与时钟请求可能并发，所以新增playback_revision保护设置，播放事件序号保护音量恢复，speech_revision继续隔离旧音色。受信弹窗一次写入、合并后续修改，后台限制并发写入，旧文档/会话不能修改新会话。使用原图标生成扩展尺寸，安装目录同步包含图像资源，权限保持不变。验证及未执行的真实Edge新版本验收见 [EXTENSION_UPDATE.md](EXTENSION_UPDATE.md)。

## D038 — 本地视频以播放器拥有的文件能力接入相同预读流程

本地文件可被外部修改，故在选定时记录文件身份及版本，读取 / 解码时核验，改变后要求重新打开；不静默混用旧播放缓存与新识别内容。浏览器默认音轨可能不等于 PyAV 首轨，当前拒绝多音轨预读，待未来明确实现统一选轨后再扩展。实际格式依系统 WebView2，首轮验证单音轨 H.264 / AAC MP4；不通过自动转码掩盖不支持的容器。已有 VLC 应用音频入口保留。生命周期、真实 GPU / 翻译 / 语音短测和剩余验收见 [LOCAL_VIDEO_LOOKAHEAD.md](LOCAL_VIDEO_LOOKAHEAD.md)。
