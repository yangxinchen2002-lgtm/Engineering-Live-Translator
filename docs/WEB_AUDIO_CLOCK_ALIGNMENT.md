# 真实声音对时修正 — 2026-11-03

用户重新打开课程窗口后确认，视频画面内的原文和中文仍固定晚 2–3 秒。此前预读解耦和主音轨选择不是该偏移的验收通过依据，原记录保留，但本次进一步用实际播放声音测量时间映射。

## 实测发现

- 当前 TUM-Live 课程的容器与音轨起点均为 1.4 秒，仅凭这个起点不能推出应提前几秒。
- 对正式内置播放器的实际活动音频会话进行 8 秒 Windows Application Loopback 采样，全部只在内存中；再与该课程本地预读解码的音频匹配。
- 首次有效测量：预读音轨位置比播放器时钟大 2.02425 秒，两个独立 3 秒片段一致，最低归一化相关度 0.902918。第二个新会话独立测得 2.00525 秒，最低相关度 0.993791，峰值与非邻近候选的间隔 0.805088。
- 因而本例中，播放器时间约 1947.150 秒对应预读音轨约 1949.155 秒。直接拿预读句首与播放器时钟比较会让字幕晚约 2 秒。该坐标差异已经实测；网站内部具体是如何产生这个差异的，尚未确定。
- Python 启动器进程树的首次诊断得到静音，不能当成有效测量。直接定位到同一 ELT 内置窗口的活动 WebView2 音频会话后，实际采样 RMS 为 0.0280，随后得到上述有效匹配。另一次启动阶段时钟不稳定的测量也被拒绝，没有用失败结果补偿。

## 正式实现

`app/web_follow/alignment.py` 使用已有的原生捕获程序、NumPy/SciPy 和 PyAV，不增加模型或云请求。目标仅来自当前 GUI 拥有的唯一内置播放器，并核验音频会话 PID、创建身份及所属进程树；不会选择其他应用。

每次最多尝试 3 次，每次采样 8 秒。将两个相隔 4 秒的独立片段分别匹配，要求相关度至少 0.55、非邻近峰值差至少 0.12、两个偏移相差不超过 120 ms，偏移限制在 ±4 秒。静音、重复音、暂停、跳转、非 1 倍速或不稳定时钟不产生有效补偿。小于 150 ms 的测量不移动字幕。失败会明确标为未完成对时，ASR/翻译继续。

内部关系：`源音轨时间 = 网页播放器时间 + 实测偏移`。

- ASR 解码、句段对象、翻译归属和 TTS 准备保留原始音轨时间。
- 后端用换算后的源时间调度预读与判断任务是否过期。
- 返回网页的句段开始/结束时间减去同一偏移，字幕和朗读同时按原播放器的时间触发，整句可读时长不变。
- 原播放器的播放、暂停、倍速、音量和进度均不由校准修改；没有硬编码 2 秒，也没有更改音频样本。
- 原文/中文仍在预读阶段识别、翻译；校准不使 DeepSeek 等到实际播放时才调用。
- 校准只用于当前媒体会话，不跨课程、重开服务或新窗口继承未经验证的数值。已经锁定的早期字幕文本/历史不会被改写。

服务端识别正式内置客户和所属 GUI 后才启动校准；Edge 扩展和独立实验不会误用另一个内置窗口的声音。采样结束/停止时释放原生辅助进程，诊断仅含数字和失败类型。没有保存用户音频、课程文字、签名媒体链接、Cookie 或密钥。

## 使用与边界

首次校准请保持原视频原声开启，并以 1 倍速连续播放约 8–30 秒。成功后可以调整播放器倍速，已测得的时间坐标差会保留到本次媒体会话结束。初始静音/消音、直接以其他倍速开始或原生捕获不可用时，会保留未校准状态，不能视为已同步。新的主界面会显示正在校准、已提前/延后多少秒，或尚未完成对时。

修正已通过仅重启字幕后台载入当前课程，不要求再次关闭课程窗口。当前仍在运行的主界面是旧模块实例，下次正常打开 ELT 会显示新增对时文字；后台诊断中的 `clock_calibrated` 和 `clock_offset_seconds` 已可读取。

校准前首次加载和测量期间，仍可能有短暂未校准字幕。音频设备实际输出、浏览器绘制、Whisper 单词时间误差及 HLS 中途不连续不等同于该坐标偏移；本轮未测系统 P50/P95，仍需用户听看验收，未把 M3/MVP 或 60 分钟稳定性标为完成。

## 测试与证据

- 最终相关自动回归 150 项通过（10.40 秒）、网页脚本 41 项通过，结果见 `artifacts/web-timebase/python-final.xml`；此前 `python-release.xml` 为 149 项通过，边缘专项 `python-edge.xml` 29 项通过。覆盖正负偏移、时间零点、正常播放/跳转、源时间不变、朗读窗口时长不变，以及不确定结果不能补偿。
- 匹配算法测试使用随机信号与噪声作为测试样本；能找到已知 ±2 秒偏移，拒绝静音、重复正弦和前后不一致的偏移。这些单元测试不是课程同步实测。
- 独立真实 WebView2/Hls.js 测试使用现有公开 MIT 文件重封装为 HLS，加 2.4 秒传输时间偏移。实际解码起点 2.356 秒，浏览器片段起点 0，播放正常。该样本用于核对方法，不代表目标网站 Video.js 的所有内部映射。
- 校准后的真实课程数值快照：`ready`、`clock_calibrated=true`、偏移 2.00525 秒；播放器位置 1947.150045、源位置 1949.155295；双语预读余量 18.285445 秒；无错误，跳窗 1（启动追赶）；采样结束后捕获辅助进程数 0。
- 生产修正测试采用真实本地 Whisper、用户已启用的 DeepSeek 和内置播放器；有正常文本 API 用量。波形校准本身不调用 API。中文 TTS 调度共用修正后的句段时段，本轮没有重新给出朗读质量/延迟统计。

数值证据：`live-before-mapping.json`、`live-applied.json`、`hls-browser.json`。公开样本复现工具：`tools/check_hls_timebase.py`，独立窗口不操作用户课程。`python-mapping.xml` 保留一次负偏移测试的失败：测试把一次 5 秒跳转误作连续播放；改为逐秒推进后通过，未修改生产跳转阈值来迎合测试。
