# 多语言、Windows 应用音源与动态追赶 — 2026-11-03

本次按用户要求新增中文、法语、俄语、意大利语、韩语，增加类似 Windows 音量合成器的应用音源选择，并将朗读追赶改为按积压字数、带缓冲期、最高基础速度1.5倍。当前源码及原生捕获程序已更新，现有桌面 EXE 直接使用；需要退出并重新打开 ELT。未新增模型、升级依赖、重打旧便携分卷或修改用户密钥。

## 使用

1. “原始语言”现可选德语、英语、日语、中文、法语、俄语、意大利语、韩语和自动。知道课程语言时直接固定选择。Auto 仍需连续可靠检测后锁定，课程换语言时停止后重开会话。
2. “音频来源”现在直接显示 **Windows 应用音频列表**，不再先选应用分类（2026-11-04 简化，见 [统一音源选择](UNIFIED_AUDIO_PICKER.md)）。先在目标应用播放一下声音，随后暂停、刷新并选择具体应用。名称、应用图标、PID、活动/空闲状态用于辨认；多个实例需自行选择。
3. 点击开始，音频连接就绪后继续播放。原文实时、整句翻译、实时预览、焦点显示和存稿沿用原操作。中文原文启用 DeepSeek 时仅忠实转为简体中文，不扩写；原文模式不会发送翻译请求。
4. “朗读”页可调整 **加速门槛**（20–1000字，默认80）和 **积压缓冲**（1–30秒，默认5）。基础语速默认1.25倍，追赶上限为1.875倍；基础2倍时上限3倍。关闭自动加速后直接使用基础语速。

## 音源边界及生命周期

使用现有 pycaw/comtypes 和官方 Core Audio 会话 API，枚举所有活动播放设备上的非过期应用会话，不控制 Windows 音量合成器窗口。活动是会话状态，不等于已检测到非零声音。空闲/暂停应用仍可被列出；应用未创建或已销毁音频会话时，要先播放一下再刷新。列表每2.5秒异步刷新，也可手动刷新。

同应用多个设备/会话合并成一行。浏览器音频辅助进程向上寻找同一可执行文件且拥有可见窗口的祖先进程；无可验证窗口祖先时保留实际音频进程，不把所有同解释器的 Python 程序混为一个源。创建时间检查防止 PID 复用造成错误归属，GUI/CLI/原生程序各自复核身份。发现阶段不读取窗口标题、网页地址或命令行，不捕获音频。

选定后复用真实 Application Loopback 的 INCLUDE_TARGET_PROCESS_TREE。通用原生选项为 `--source process`；CLI 对应 `--source sessions`。旧 VLC/Chrome/Edge 筛选仅保留在 CLI / 内部兼容接口，桌面界面统一用应用列表。捕获是应用进程树范围，可能包含同一应用的多个窗口/标签页和播放设备，不能等同于单个标签页或单条音频会话。

系统声音/PID0、没有唯一归属 PID 的跨进程共享会话、无权访问的进程不作为可单独捕获的源；当前 ELT 及已核验的子进程被排除，避免选中本窗口的朗读。受保护媒体仍遵守 Windows 的限制，没有切到全系统或麦克风的兜底路径。枚举最多256个会话、128个应用，超限明确报错；诊断列表有上限。

Core Audio 对象只在发现工作线程的 COM 公寓内创建和释放，跨线程只传递不可变进程元数据；异常 traceback 的局部引用也在 CoUninitialize 前清理。音源图标从本机应用文件读取。原声音量调整继续由独立 guardian 管理，只作用于所选、身份已核验的进程树，恢复和手动覆盖规则不变。

官方依据：[Audio Sessions](https://learn.microsoft.com/en-us/windows/win32/coreaudio/audio-sessions)、[GetSessionEnumerator](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessionmanager2-getsessionenumerator)、[ApplicationLoopback 示例](https://github.com/microsoft/Windows-classic-samples/tree/main/Samples/ApplicationLoopback)、[pycaw](https://github.com/AndreMiras/pycaw)。

## 追赶策略

待播字数为尚未开始朗读的队列及预生成文本中的字母/汉字/数字数，不计空白标点，不将正在播放句子的历史等待时间当成新的积压，也不估造词级播放进度。首批音频写入播放缓冲前不会因模型加载时间而触发加速。

默认达到80字并持续5秒后启动追赶；待播字数持续低于或等于40字3秒后退出。进入后的目标倍率随字数增长，80字约为基础×1.1，160字约×1.3，240字及以上最高×1.5。提高门槛后，这些边界按比例调整。倍率逐渐靠近目标，每秒最多增加0.08或减少0.10，避免开关抖动；等待时间本身不会触发加速。

实际向音频滤镜下发自动变速最多每200毫秒一次；保持同一音频流，不重建播放设备、不清空译文、不合并相邻字幕。高于2倍时串联两个不超过2倍的 atempo 阶段。现有防断流余量、生成速度估计、恢复缓冲和32MiB PCM上限继续有效。状态显示真实控制语速、待播字数/段数，以及“积压缓冲中”或“自动追赶”。新参数会随偏好保存，旧设置文件通过默认值兼容。

连续变速测试曾发现每20ms下发指令造成时长偏差：8秒440Hz信号、基础2倍的上升过程中，输出比积分期望短约4.17%。限制指令频率后，连续变速的时长、音调与非零样本检查通过，没有放宽原测试门槛。atempo 的波形对齐来源见 [FFmpeg 实现](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/af_atempo.c)。这是合成信号测试，不代表真人朗读自然度评分。

## 自行复验

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.main list --source sessions
.\.venv\Scripts\python.exe tools/check_application_audio.py --output docs/evidence/my-application-audio.json
```

第二条命令会明确播放两个自有应用的轻声短测试音，执行隔离、暂停、恢复和退出检查；不加载识别/朗读模型、不调用API、不永久保存音频。报告文件要求使用新路径。

人工使用时分别播放新增语言课程，核查原文、中文与存稿；再用常用播放器、会议或浏览器应用选择其真实音源，确认范围。朗读在等待内容少时保持基础速度，持续积压后提速，积压减少后渐降；可调整80字/5秒以适合课程。

新增语言真实课程的识别/翻译质量、真人朗读连续变速的听感、各第三方应用兼容性、长时间稳定性及原有完整 M3/MVP 验收仍待执行。没有将短测试音或 Mock 结果解释为这些项目通过。
