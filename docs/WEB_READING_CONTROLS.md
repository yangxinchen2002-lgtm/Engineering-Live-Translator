# 内置课程窗口朗读修复与顶部设置

2026-11-03。修正“有双语字幕、没有中文声音”，并在现有 ELT 课程窗口顶部提供快捷设置。继续使用同一个 ELT.exe，没有新增用户项目、模型下载或另一套配置。

## 使用

课程窗口顶部的朗读设置区域可直接调整（最新分组样式见 [顶部整理](NATIVE_TOOLBAR_POLISH.md)）：

- 中文朗读开关。
- 模型：本地 0.6B、本地 1.7B、Windows 系统音色。
- 对应引擎的音色。
- 基础语速：1.00–2.00 倍。
- 中文音量：0–100%。

语速和音量立即更新中文播放；开关不停止原文识别与翻译。正常速度足够时按基础语速读完并等待，时间不足才加速。模型或音色改变时释放旧合成器，清除旧语音引用并准备新语音，字幕和视频时钟继续；首次加载仍需要等待。不会静默切换模型。新设置通过原主界面保存到既有偏好；已经打开的旧版主界面应在正常结束本次使用后重新启动，才能加载完整的模型/音色同步逻辑。

视频播放、暂停、位置和倍速由原网页播放器控制。关闭 ELT 课程窗口会关闭网页；本次验证只重启字幕后台，没有重载、跳转或暂停正在播放的用户视频。

## 根因与修复

真实课程首次诊断显示：Qwen 1.7B 在 CUDA 上已生成 19 段语音；内置播放器请求 19 次，成功读取 0 次，失败 19 次，开始播放 0 次。问题发生在生成后的本机 HTTP 读取环节，不能用此前的独立测试句播放成功代替课程链路通过。

播放器使用 `X-ELT-Lab-Token` 请求头验证本机连接，但媒体路由原先只检查 URL 的 `token`。服务现在接受原有请求头；需要 URL 验证的 HTML 媒体元素仍可使用原方式。两种方式都使用同一个会话随机令牌，并继续核验 Host、Origin 和允许访问的会话音频文件；没有开放匿名音频访问，也没有把本机令牌注入课程网页。

另外增加生成、跳过、取文件、开始播放、播放结束、自动播放受阻等独立计数。生成错误仅记录错误类型/阶段，不把课程文字或模型库输出写入普通诊断。WebView2 的自动播放参数仅作用于 ELT 子进程；被阻止时显示允许中文朗读的入口，保持原视频继续播放。

设置通过有界、合并的本机控制消息传递。模型/音色有独立 `speech_revision`，旧文件与迟到结果不能覆盖新选择；文件名包含该版本。语音队列仍为 8 句，在途同一句去重，语音合成不阻塞 ASR。关闭朗读会立即停止自己的 Audio，不修改原视频。

## 复验

在 ELT 内置窗口播放有讲话的受支持课程，启动字幕，确认有原文、译文及中文声音。模型加载时保持视频原状态即可；检查顶部朗读开关、语速和音量，原文与翻译应继续显示。切换音色/模型后允许准备时间，旧音色的迟到音频不得播放。诊断详情中的 `tts.generated` 与 `playback_diagnostics` 应能分别看到生成、取文件和播放结果。
